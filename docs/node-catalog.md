# 节点清单与端口分配

## MainApp 启动

MainApp 启动时请求 `GET /api/v1/node-catalog?channel=stable`。开发构建请求 `channel=dev`，以实际安装的构建通道为准。Launcher 继续负责程序更新和启动。

- `200` 返回 `nodes`（节点 ID 和名称）、`updated_at`（节点目录的 Unix 毫秒更新时间）、`min_frpc_version` 和 `blocked: false`。MainApp 校验响应后才允许选择线路和启动映射。低于最低版本时提示更新 MinecraftTools。
- `403` 返回 `detail.code = ip_blacklisted`、`detail.blocked = true` 和 `detail.reason`。MainApp 显示封禁理由，禁用映射。响应不含节点或连接信息。
- 清单按控制端和通道在用户数据目录中持久化。配置变化时原子替换，空清单也会替换旧缓存。请求失败时可显示缓存中的线路名称，重试成功后才能启动映射。封禁时界面清空线路。

## 启动映射

1. 用户选节点并填写本地端口。已有安装身份时，MainApp 只发一次 `POST /api/v1/tunnels/register`，请求体是 `node_id` 和实际安装构建的通道 `channel`。
2. Control Server 校验客户端 IP、节点状态和发布通道：节点的 `client_channel` 必须是请求通道本身或 `both`，否则返回 `404`，错误代码为 `node_not_found`（与未发布一致，不泄露节点是否存在）。不带 `channel` 的旧客户端按 `stable` 处理，只能使用 stable/both 节点。`2026-11-26-7` 之前的客户端内嵌节点表、不请求清单，升级后才能使用 dev 节点。通过校验后在生效范围内排除占用、预留和封禁的端口。选端口和写预留发生在同一个事务。没有空闲端口时返回 `409`，错误代码为 `no_available_port`。
3. 成功时返回 `remote_port`、隧道凭证、frpc 连接主机及端口和玩家访问主机。需要 frps 登录令牌的线路也在此时返回可下发给客户端的令牌。MainApp 用分配结果启动 frpc，确认映射成功后显示可分享地址。失败或停止时释放预留，请求中断留下的预留会到期。

服务端不提供静态节点列表；MainApp 只使用 `GET /api/v1/node-catalog`，注册时提交 `node_id` 和构建通道，端口由控制端分配。

## 管理与上线

- Agent 首次连上控制端会自动出现在「节点」页面，默认未发布。管理台确认公网地址、允许端口和发布通道后，节点才会进入清单并接受注册。默认 `public_host` 取连接来源 IP；经 nginx 转发时需要在发布前改成节点公网 IP 或域名。
- 节点快照里的代理必须能对上控制端一条未过期的预约（`tunnel_id` 和 `tunnel_proof`）。对不上时，未发布节点立即封禁该端口；其它节点给 30 秒宽限，仍未绑定预约就自动封禁，封禁来源记为 `unauthorized`。同一公网 IP 在统计窗口内累计达到触发条数的这种无预约隧道、且没有合法隧道时，自动拉黑该 IP。条数、窗口和时长在管理台「设定」页配置，默认 3 条 / 10 分钟 / 24 小时；关闭自动拉黑后仍会封禁隧道，只是不再自动加黑名单。管理台「隧道」页会把没有预约的隧道标记为「未授权」。
- 把节点改为「未发布」时，该节点上存活中的隧道会一并封禁，客户端轮询会看到对应状态；快照里即使带着有效预约的代理也会被关闭。「未发布」不再只是从清单和注册接口里消失。重新发布该节点会解除这些由下架产生的封禁。
- 「允许端口」是一个输入框，逗号分隔、段内用横杠，例如 `30000-30010,30015`。端口须在 1024–65535 之间，并落在 Agent 上报的节点部署范围内；保存后等待 Agent 确认，列表会显示待确认值。管理员分配只在这个集合内取端口。部署范围由节点侧决定，扩容和迁移步骤见[节点端口容量](node-ports.md)。
- 节点离线、没有实时映射、没有未释放的预留、没有生效中的封禁时，可以删除节点；删除会一并清理该节点的历史映射、封禁、扫描和大厅记录，且不可恢复。
- 多段端口需要节点运行支持 `ranges` 的新 Agent。旧 Agent 只会按首尾范围生效，配置多段前先升级节点 Agent。
- 玩家访问主机与 frpc 连接主机可分别配置。存在实时映射、预留或封禁记录时，公网主机变更仍遵守后台原有约束。已部署的 frps `allowPorts` 和 Agent 策略继续决定服务端可分配的范围。
- 新节点不再配置 frpc 登录令牌；管理台也不再显示该字段。旧节点数据库中已有令牌的客户端继续收到令牌，直到所有节点重建后再移除兼容代码。
- `CONTROL_MIN_FRPC_VERSION` 在 Control Server 上配置，默认 `0.72.0`。发布前确认软件所带的 frpc 版本满足要求。
- 普通发布先升级 Control Server。需要多段允许端口时，先升级对应节点 Agent，再改端口配置；随后按通道配置线路，确认清单和端口预留后再发布新版 MainApp。
